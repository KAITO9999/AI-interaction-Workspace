# workflow — 作業手順（初回/随時/最終・cache・検証）
優先順位はカスタム指示に従う。ここは実行手順と振り分け。
関連: [environment](environment.md) / [debug-and-reuse](debug-and-reuse.md) / [quality-and-migration](quality-and-migration.md) / [research-and-instructions](research-and-instructions.md)

目的: 品質・正確性・保守性。改修・検索・抽象化・ツール導入自体を成果としない。既存実装を尊重し、効果が見込める変更だけ行う。

核心: 完了条件と検証方法を先に決める / 小さく変更して即検証 / 同一修正2回失敗で仮説か経路を変える / 未実行の検証を完了と書かない / 完了後は自作の予定書・cache・一時物を片付ける

## 規模
- 小: 誤字・定数・文言1箇所 → 読む→修正→確認
- 中: 複数ファイル/既存ロジック/仕様解釈 → 初回・随時・最終
- 大: 原因不明/新規群/大改修/環境差/上流統合/再失敗 → 中＋作業ファイル＋差分読み戻し
迷ったら中以上。単純作業に計画・検索・記録を足さない。

## 初回
1. 目的/完了条件/固定条件/禁止事項/変更範囲を整理。成功条件は検証可能な形にする
2. テスト・確認方法を決める。検証不能なら代替を探す。無理なら未検証とする
3. 対象・依存・呼び出し元・設定・履歴・規約を読む。API/引数/戻り値は推測せず確認
4. 必要なら [environment](environment.md) / [debug-and-reuse](debug-and-reuse.md) / [research-and-instructions](research-and-instructions.md)
5. 中以上は対象/依存順/リスク/検証/復旧を計画。破壊的変更は影響と復旧を示し承認後に実行
- 質問は結果を左右し、文脈と既存資料から決められない事項に限る
- 新環境は入口資料(README/AGENTS.md等)から。同一会話の話題変更・継続で初期化を繰り返さない

## 随時
- 小さく変更→変更箇所に合う検証
- 計画外変更が必要なら根拠を確認し計画と成功条件を更新
- 決定/原因/検索区切りで作業ファイルを更新し確認手順を見直す
- 同一修正2回失敗 → 失敗パターンを記録し [debug-and-reuse](debug-and-reuse.md) で仮説か経路を変える

## 最終
- 差分を読み戻し、意図外変更/欠落/残留物/古いコメント/デバッグ出力を確認
- 完了条件を実行結果で照合。テスト通過のために期待値や仕様を変えない
- 報告: 変更 / 判断根拠 / 検証結果 / 未検証範囲 / 残課題。範囲外改善は提案に分ける
- 後片付けを行う

## 長期作業・cache
- 中以上: WORK.md 等に 目的/完了条件/固定条件/依存/決定と根拠/確認済み事実/仮説/試行結果/未解決/次手順/作成物の場所 を区分記録。原票・履歴は上書きしない
- 検索が多い場合のみ RESEARCH.md を分け、話題/項目/出典URL・版・日付/根拠/適用条件/反証/未確認/判断への影響を記録。全文は貼らず WORK.md からリンク
- 区切りごとに残す価値・次対象・探索手順を再評価。独立根拠が増えず判断が安定したら費用対効果で止める
- 圧縮時: 元指示/ソースと照合し 確定/仮説/決定/失敗済み経路/未解決/次手順 を分ける。根拠と再確認先を保ち、重複・用済みのみ削る
- 新セッション/圧縮後: 作業ファイルと関連資料の該当箇所だけ読む

## 後片付け
対象: 自作の予定書/作業ファイル/cache/調査メモ/一時物/ログ/生成物/BGプロセス(Remote含む)
1. 作成時に場所を記録し完了時に一覧化
2. 再利用できる決定/仕様/未確認/次手順だけ既存資料へ移す。原票/履歴/ユーザーファイルは保全
3. 自作物だけ削除。削除前にパス/内容/参照を確認
4. プロセス/ロック/一時マウントを停止・解除
5. 削除/保全/削除不可を報告
- 継続中は予定書とcacheを残し再開手順を1つ書く

## 検証
1. 完了条件→確認コマンドを先に決める。バグは再現テストを書いて失敗確認から直す
2. 構文/型/Lint → 単体 → 結合・実行 → 実環境の順で、変更リスクに合う範囲
3. 不安定テストは再実行回数と結果を記録。1回通過で完了扱いしない

| 対象 | 既定経路 |
|---|---|
| 構文/型/Lint/ロジック | AI側Linux/CI |
| 重いビルド(Java/Gradle/APK/AAB/NDK) | GitHub Actions/AI側Linux。端末は高負荷のため非推奨 |
| 権限/パス/ハード/OS・CPU差/GPU/実機 | 実環境(代替不能時) |
| ファイル形式の静的検査 | AgentKit `audit-addon` / `mobile_test`(静的のみ) |

- パス/権限/ハード/OS/実行者を実際の実行経路に寄せる。届かなければ検証不可と明記し手順を渡す
- 静的検査≠実行 / インストール成功≠タスク成功 / ワークフロー存在≠ビルド成功 / ソース確認≠動作確認
- 記録: コマンド/終了状態/要点出力/対象版・環境。確認済み/解釈/未確認を分ける
